# Security, Privacy & Reliability — devdoctor-ai

## 1. Threat Model & Security Principles

`devdoctor-ai` operates on developer workstations and environments where sensitive source code, environment variables, credentials, and error diagnostics coexist. The application enforces a strict zero-trust posture toward AI-generated commands and uploaded image contents.

---

## 2. Image Handling & Privacy Guarantees

### 2.1 Zero Persistent Retention
- Screenshots are parsed directly in memory as base64 buffers.
- The server does **not** persist screenshots to disk, databases, object stores (S3), or caches.
- Once the model completes inference and the JSON response is delivered, image buffers are immediately eligible for V8 garbage collection.

### 2.2 Local Inference First
- When running in the default Ollama mode, all multimodal image tokens remain strictly on the user's localhost (`127.0.0.1:11434`).
- No external network packets leave the machine, preventing code leaks or compliance violations in corporate or proprietary codebases.

### 2.3 Cloud Inference Safeguards (Google AI Studio / Alternative)
- If configured for cloud inference via `GEMINI_API_KEY`, images are transmitted over TLS 1.3 to Google Generative AI endpoints.
- User data processed under standard developer API terms is not used for model training unless opted in.

### 2.4 User Warnings Against Sensitive Data
Both the upload interface and API documentation prominently instruct users:
> **Security Notice**: Do NOT upload screenshots containing API keys, private passwords, `.env` files, production database connection strings, or Personally Identifiable Information (PII).

---

## 3. Defense Against Destructive AI Advice

### 3.1 Strict Non-Autonomous Policy
- **No Automatic Shell Execution**: The application explicitly lacks any endpoint or capability to run commands on the user's host machine.
- All actions are presented in text blocks with click-to-copy buttons, requiring deliberate human developer review.

### 3.2 Risk Categorization Badges
Every generated troubleshooting step is scored with a risk rating:
- `Safe`: Read-only queries, inspecting logs, checking versions (e.g., `node -v`, `git status`).
- `Moderate`: Installing packages, rebuilding caches (e.g., `npm install`, `docker compose restart`).
- `Risky`: Deleting directories, resetting branches, modifying file permissions (e.g., `rm -rf`, `git reset --hard`, `chmod 777`).

For any `Risky` step, devdoctor-ai requires an explicit rollback explanation detailing how the developer can recover if the action fails.

### 3.3 Epistemic Humility (Evidence vs. Inference)
- The system visually separates **Visible Evidence** (verbatim text read off the screenshot) from **Inference / Hypotheses** (speculative causes generated by the model).
- The UI never asserts that a fix is guaranteed to work; confidence scores and uncertainty flags are explicitly displayed.

---

## 4. Input Validation & API Hardening

| Check | Boundary | Failure Action |
| :--- | :--- | :--- |
| **Max Payload Size** | Decoded buffer $\le 10$ MB | HTTP 413 `FILE_TOO_LARGE` |
| **MIME Type** | `image/png`, `image/jpeg`, `image/webp` | HTTP 400 `INVALID_FILE_TYPE` |
| **Payload Structure** | Valid Base64 Data URI or clean Base64 | HTTP 400 `MALFORMED_PAYLOAD` |
| **Request Timeout** | 60 seconds per inference request | HTTP 504 Gateway Timeout |
| **JSON Injection Defense**| Strict schema parser with regex sanitization | Return fallback safe diagnosis |

---

## 5. Credential Protection
- API keys (`GEMINI_API_KEY`, `HF_API_TOKEN`) are read exclusively from environment variables on the backend.
- Neither Vite nor the Express API ever exposes secret environment keys in client bundles or public endpoints.
- `.env` is committed to `.gitignore` and `.env.example` contains only empty placeholder strings.
